專案問答 FAQ

關於本研究系統的常見問題，涵蓋資料來源、模型架構、預測方法與使用說明。

🔍
資料清洗
資料清洗流程頁面的用途是什麼？+
資料清洗流程頁面提供視覺化的完整清洗過程展示，包含：
① 匯入原始 104 CSV 職缺資料
② 欄位轉換前後對照（前 10 筆預覽）
③ 各清洗步驟逐步說明與移除統計
④ 清洗後資料圖表（薪資分布、地區、年資、產業分布）
清洗後可直接下載處理完畢的 CSV 供後續建模使用。
清洗時會移除哪些類型的資料？+
清洗規則共分以下類別：
  • 職稱空值：職務名稱為空白或全為特殊符號者移除
  • 時薪排除：薪資型態為「時薪」的職缺不適合月薪預測，整列移除
  • 最低薪資為 0：salaryMin 為 0 代表資料不完整，移除
  • Min > Max：最低薪高於最高薪為資料錯誤，移除
  • 低於基本工資：低於法定基本工資 27,470 元者移除
  • 高於 500 萬：薪資超過 500 萬屬異常高值，移除
  • 年薪換算超標：年薪型態除以 12 後超過 50 萬者移除
薪資型態欄位（jobSalaryType）有什麼作用？+
jobSalaryType 記錄職缺薪資計算方式，常見值包含「月薪」、「年薪」、「時薪」。 清洗階段用於：
  • 「時薪」職缺與月薪預測目標不相容，直接排除
  • 「年薪」職缺換算月薪（÷12）後，若超過 50 萬視為異常排除
  • 「月薪」職缺直接使用 salaryMin / salaryMax 數值
清洗前後的對照表格中可看到每筆資料的薪資型態標示。
上傳大型 CSV 時為何需要等待？+
系統採用純前端 JavaScript 進行 CSV 解析，約每 500 筆讓出一次瀏覽器控制權以避免畫面卡死。 3 萬筆左右的資料在一般電腦約需 10–30 秒。

上傳過程中 overlay 會顯示「資料上傳中請耐心等候」並即時更新解析進度， 請等待進度完成後再操作頁面。若瀏覽器詢問是否等待，請選擇「等待」。
特徵變數模擬分析頁面是做什麼的？+
特徵變數模擬分析頁面（catboost_training.html）提供互動式的模型特徵探索：
  • 調整地區、年資、產業、員工規模等特徵，即時觀察對薪資預測的影響
  • 視覺化 CatBoost 特徵重要性排序
  • 展示模型訓練流程與參數設定說明
適合用於報告簡報時示範「改變哪個條件會讓薪資變化」的直觀解說。
資料來源
資料從哪裡取得？+
本研究資料來自 104 人力銀行公開職缺頁面，透過 Python 爬蟲（requests + BeautifulSoup）擷取， 僅供學術研究用途，不涉及商業應用。資料擷取期間為 2024 年，共收集逾萬筆有效職缺記錄。
資料包含哪些欄位？+
主要欄位包括：
  • jobTitles — 職務名稱
  • jobCategory — 職務類別
  • jobLocationAt — 工作地區
  • jobRqYear — 年資要求
  • jobCompanyIndustry — 公司產業別
  • salaryMin / salaryMax — 月薪最低／最高（目標變數）
  • employeeCount — 公司員工人數
資料如何前處理？+
前處理步驟包括：
① 移除薪資欄位為空白或「面議」的記錄（保留有明確數字的樣本）
② 薪資異常值過濾（低於基本工資或高於 300 萬者排除）
③ 職務名稱文字正規化（去除特殊符號、統一繁體中文）
④ 類別欄位 Label Encoding / Target Encoding
⑤ 職務語意向量化（TF-IDF + K-Means 職務分群）
訓練資料共有多少筆？+
前處理後約有 數千至萬筆有效薪資記錄（確切數量可在首頁的「訓練樣本數」查看， 系統啟動後由 /health API 即時回傳）。
模型架構
使用了哪些預測模型？+
本研究採用三種梯度提升演算法：
  • CatBoost — 對類別特徵原生支援，無需手動 One-Hot Encoding
  • LightGBM — 訓練速度快，適合大規模資料
  • XGBoost — 穩定性高，廣泛應用於結構化資料競賽
每種模型分別訓練「最低薪」與「最高薪」共兩個子模型，合計 6 個模型。
模型的評估指標為何？+
主要使用以下指標評估預測效果：
  • MAE（平均絕對誤差）— 預測值與實際值差距的平均，單位為新台幣元
  • RMSE（均方根誤差）— 對大誤差更敏感
  • R²（決定係數）— 模型解釋資料變異的比例，越接近 1 越好
首頁顯示的 MAE 為 CatBoost 最高薪模型的測試集表現。
什麼是職務分群（job_cluster）？+
職務分群是以 TF-IDF + K-Means 對職務名稱與類別文字進行非監督式分群， 將職缺歸入數個語意相近的群組（如「軟體工程」、「資料科學」、「業務行銷」等）。 分群結果作為模型的額外特徵輸入，有助於提升薪資預測精度。
最重要的預測特徵是什麼？+
根據 CatBoost 特徵重要性分析（首頁圖表可查看）， 影響薪資預測最關鍵的特徵通常為：
  • 職務類別（jobCategory）
  • 工作年資（jobRqYear）
  • 工作地區（jobLocationAt）
  • 職務分群（job_cluster）
  • 公司員工規模（employeeCount）
三種模型
CatBoost — 什麼是 CatBoost？它有什麼優勢？+
CatBoost 由 Yandex 開發，全名 Categorical Boosting，是一種梯度提升決策樹演算法。

主要優勢：
  • 原生支援類別特徵：不需手動 One-Hot Encoding，直接輸入「台北市」、「軟體工程師」等文字欄位，內部自動處理
  • Ordered Boosting：使用排列（permutation）技巧降低訓練資料洩漏，減少過擬合
  • 對稱樹結構：預測速度快，適合部署
  • 本研究主力模型：特徵重要性分析以 CatBoost 為基準，首頁 MAE 指標亦來自此模型
本研究 CatBoost 分別訓練「最低薪」與「最高薪」兩個子模型。
LightGBM — 什麼是 LightGBM？與 CatBoost 有何不同？+
LightGBM 由 Microsoft 開發，採用基於梯度的單邊採樣（GOSS）與互斥特徵捆綁（EFB）技術。

主要特點：
  • 訓練速度快：Leaf-wise（葉節點優先）生長策略，比傳統 Level-wise 更快收斂
  • 記憶體效率高：直方圖演算法大幅降低記憶體用量，適合大規模資料集
  • 需要 Label Encoding：類別特徵須先轉換為數值，與 CatBoost 原生支援不同
  • 適合資料量大時：本研究資料量達數萬筆，LightGBM 訓練速度優勢明顯
在三模型工作台中可直接比較 LightGBM 與其他模型的預測差異。
XGBoost — 什麼是 XGBoost？為何仍被廣泛使用？+
XGBoost（Extreme Gradient Boosting）由陳天奇開發，是競賽社群長期主流的梯度提升框架。

主要特點：
  • 穩定可靠：Level-wise 樹生長策略較保守，泛化能力強，不易過擬合
  • 正規化支援：內建 L1（Lasso）與 L2（Ridge）正規化，控制模型複雜度
  • 跨平台成熟：文件豐富、社群支援最廣泛，容易除錯與調參
  • 基準比較價值：作為最成熟的梯度提升方法，適合與 CatBoost / LightGBM 對比驗證
本研究以 XGBoost 作為對照基準，確認其他兩種模型在薪資預測任務上的相對表現。
三個模型的預測結果差異大嗎？以哪個為準？+
三個模型預測結果通常在同一區間內，但細部數字因演算法不同略有差異：
  • 預測差距在 5,000–15,000 元以內屬正常範圍
  • 若三者差距過大（>3 萬），通常代表該職務在訓練資料中樣本偏少
  • 建議以 CatBoost 為主要參考，因其對本資料集的類別特徵處理最自然
  • 三模型工作台（salary_dashboard.html）可同時對比三者輸出，供使用者自行判斷
模型驗證頁面提供各模型的 MAE / RMSE / R² 指標，可作為選擇依據。
為什麼每種模型要分別訓練最低薪與最高薪？+
104 職缺薪資以「區間」呈現（例如 50,000–80,000 元），最低薪與最高薪的影響因素與分布不完全相同：
  • 最低薪：較受法定基本工資、公司薪酬下限政策影響，分布較集中
  • 最高薪：受職務天花板、經驗加成、績效彈性影響，分布更分散
分開訓練讓每個子模型專注優化單一目標，整體比單一模型同時預測區間的方式更準確。 合計三模型 × 兩個子模型 = 共 6 個模型。
預測方法
輸入職務名稱後，模型如何處理？+
系統處理流程如下：
① 將職務名稱與勾選的職務類別合併為 job_text 字串
② 以訓練時的 TF-IDF 向量器轉換為數值向量
③ 透過已訓練的 K-Means 模型找出最近的職務分群
④ 結合地區、年資、產業等特徵組成完整輸入向量
⑤ 輸入 CatBoost 模型，輸出最低薪與最高薪預測值
104 面議薪資預測（salary-url）如何運作？+
使用者貼上 104 職缺網址後，系統步驟為：
① 後端呼叫 /predict-url API，爬取該職缺頁面結構化資料
② 自動解析職務名稱、地區、年資要求等欄位
③ 帶入三個模型（CatBoost / LightGBM / XGBoost）分別預測
④ 回傳各模型的薪資區間，供使用者參考比較

注意：面議職缺因無公開薪資數字，預測結果為模型估算，不代表公司實際核薪。
「職務類別建議」是怎麼產生的？+
當使用者輸入職務名稱後，前端呼叫 /related-categories API， 後端以 TF-IDF 相似度計算，從訓練資料中的職務類別找出語意最相近的前 12 個類別， 回傳給使用者勾選確認，以精準控制模型的 jobCategory 輸入。
使用說明
如何啟動本系統？+
系統由一個靜態 HTTP 伺服器提供所有頁面：
  • 進入專案目錄 SPA Model/
  • 執行 python salary_server.py
  • 瀏覽器開啟 http://127.0.0.1:5001 即可使用
若需外網存取，可搭配 ngrok http 5001 建立公開連結。
「選填欄位」要不要填？+
選填欄位（公司產業別、招募部門、員工人數等）不填也能預測， 系統會帶入 Unknown 或 0 作為預設值。 但根據特徵重要性分析，補充公司資訊可適度提升預測精度，建議盡量填寫。
各頁面功能說明+
  • 研究報告 本研究簡報投影片展示
  • 資料清洗流程 匯入 CSV、視覺化清洗過程與結果圖表、下載淨化後資料
  • 特徵變數模擬分析 調整特徵即時觀察薪資影響、CatBoost 訓練說明
  • 三模型工作台 同時輸出 CatBoost / LightGBM / XGBoost 預測結果對照
  • 模型驗證 各模型測試集 MAE / RMSE / R² 指標比較
  • 薪資預測 單一職缺薪資預測，含地區薪資分布與特徵重要性圖表
  • 104 面議預測 貼上職缺網址自動爬取資料並三模型同步預測
研究限制
預測結果準確嗎？+
模型預測結果具有統計意義，但存在以下限制：
  • 薪資受個人談判能力、面試表現等非結構化因素影響，模型無法捕捉
  • 資料為某段時間的快照，不反映最新市場行情
  • 面議職缺本身薪資範圍廣，預測區間較大
  • 小眾職類樣本數不足，預測精度相對較低
預測結果應作為參考區間使用，不宜作為唯一決策依據。
資料是否有偏差（Bias）？+
存在以下潛在偏差：
  • 樣本偏差：僅涵蓋公開職缺，內部晉升或獵頭職缺未計入
  • 薪資揭露偏差：願意公開薪資的職缺可能集中於特定產業或規模
  • 地區偏差：台北市樣本比例遠高於其他縣市
  • 職類偏差：科技、資訊相關職缺佔比較高
本系統可以商業使用嗎？+
本系統為學術研究專題，所有資料爬取僅供研究分析用途。 若需商業應用，應洽 104 人力銀行官方 API，並遵守其服務條款。 本研究不對任何依據本系統預測結果所做的薪資決策負責。
